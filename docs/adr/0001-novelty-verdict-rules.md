# ADR 0001：查新判读用机械规则，并保留"无法判断"档

- 状态：已采纳
- 日期：2026-10-29

## 背景

最初的做法是把命中数丢给 LLM，让它说"这个方向有没有机会"。跑了一轮真实检索后发现两类错误：

1. **把全零当空白**。检索式 `草稿模型 KV 缺失 重建 预测` 命中 0，被解读为"技术空白，可以立项"。
   实际上中文专利简单检索是 AND 语义，5 个词的组合天然为 0；减词到 4 个词就能查到 5 件。
2. **把红海当机会**。`GPU NPU 压缩 KV缓存 传输` 命中 87 件（华为 21+16），仍被判"有交叉点机会"。

## 决策

判读改为纯函数、可单测的四档规则，LLM 只负责生成选题，不再参与判定：

| 判读 | 条件 |
|---|---|
| `red-ocean` | 任一检索式 ≥50 命中 |
| `opportunity` | 有 1–5 命中且无红海；或全部落在 6–49 |
| `gap` | 存在 0 命中但非全零 |
| `inconclusive` | 全部 0 命中 / 全部解析失败 |

配套：全零时自动减词重试一次（去尾词，仍 ≥3 词），重试结果标注"（减词）"。

## 后果

- 判读结论可复核、可回归（`verdict.test.ts` 覆盖 5 类输入）。
- 用户可能看到更多 `inconclusive`——这是**诚实的代价**：它提示"检索式要改"，而不是给出一个假的空白结论。
- 命中数 ≤5 的阈值来自实测：本领域真实交叉带命中数在 0–9 之间，50 以上基本是大厂主线布局。
